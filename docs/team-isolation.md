# 팀별 데이터와 작업 분리

학생 화면의 팀 이름에 해당하는 자료·코드·대화·이전 버전만 불러옵니다. 같은 팀원은 같은 작업을 공유합니다. 테스트팀에 이전에 저장한 파일은 테스트팀으로 재접속하면 다시 보일 수 있습니다. 이것만으로 다른 팀 자료가 섞였다는 의미는 아닙니다. 기존 팀의 저장 데이터는 삭제하지 않았습니다.

## 차단한 경로

- 같은 브라우저의 다른 탭에서 로그인 팀을 바꿨는데 기존 탭이 이전 팀 작업을 새 로그인 세션으로 전송하는 경우.
- 팀을 전환하는 동안 읽고 있던 파일, AI 결과, 저장 응답이 늦게 도착해 다음 팀의 상태를 바꾸는 경우.
- 요청 초안·API 붙여넣기·코드 편집·수정 제안·미리보기와 사용량이 팀 전환 뒤 남는 경우.
- 소유 팀이 명시되지 않았거나 다른 팀 소유인 기기 임시 저장을 자동 복원하는 경우.
- 로그인 없이 둘러보기에서 이전 사용자가 남긴 파일을 자동 복원하는 경우.

## 구현

1. 자료 조회·저장·AI 호출의 `x-hyfl-team-id`를 실제 인증 세션과 비교합니다. 일치하지 않으면 데이터 반환·쓰기·AI 호출/사용량 예약 전에 거절합니다. 응답에도 소유 팀을 붙이고 클라이언트가 재확인합니다. 이 헤더는 로그인 인증을 대신하지 않습니다.
2. 다른 탭에서 팀을 바꾸면 기존 화면을 비우고 재로그인을 안내합니다. 탭을 다시 활성화할 때도 세션을 확인합니다. 모든 요청에는 작업실 세대 번호를 적용해 이전 화면의 응답을 무시합니다.
3. 팀 전환·로그아웃 때 요청창, API 입력, 파일 선택, 코드·자료·대화·이전 버전·수정 제안과 미리보기를 비웁니다. 파일 읽기 완료 뒤에도 세대 번호를 검사합니다.
4. 학생 임시 저장에는 소유 팀 ID를 명시합니다. 소유자가 없는 예전 임시 저장은 자동 복원하지 않으며 원본을 삭제하지 않습니다. 서버의 해당 팀 저장 자료는 유지합니다.
5. 둘러보기는 팀 자료를 읽거나 저장하지 않고, 이전 둘러보기 자료도 자동 복원하지 않습니다. 새로고침 시 초기화됩니다. 보관이 필요하면 HTML/프로젝트 백업을 내려받습니다.

예전 화면처럼 팀 식별 정보를 보내지 않는 클라이언트의 자료 조회·저장·AI 요청은 428과 새로고침 안내를 반환합니다. 운영 반영 시 열린 예전 탭을 새로고침하고 팀으로 재접속해야 합니다.

## 검증 (2026-10-26)

- 전체 테스트 69개·구문 검사·빌드·diff 검사 통과.
- 서로 다른 합성 팀 A/B의 자료·코드·대화·기록을 실제 서버 핸들러와 격리 저장소에서 저장/조회했습니다. 다른 팀 ID의 조회·덮어쓰기·AI 호출·로그아웃이 거절되고 원래 데이터와 사용량이 유지되는 것을 확인했습니다.
- 실제 클라이언트 코드를 VM과 DOM/통신 어댑터에서 실행해 팀 전환/로그아웃, 잘못된 소유자의 임시 저장·응답, 늦은 파일/AI/저장 응답, 다른 탭 전환, 둘러보기 초기화를 검증했습니다.
- 실제 배포의 서로 다른 학생 팀 두 계정으로 전환하는 브라우저 확인은 아직 수행하지 않았습니다. 합성 테스트는 실제 계정 검증으로 표시하지 않습니다.
- 보호된 Preview에서 첫 진입·둘러보기의 자료 초기화와 파일 첨부·그래프 표시를 별도로 확인합니다. 운영 main에는 아직 반영하지 않았습니다.
