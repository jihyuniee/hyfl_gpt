## 실제로 수행한 자동 검증

실제 기관 응답의 필드·봉투 구조를 따른 **가상 값 JSON**을 사용했습니다. 기관 API를 호출해 가져온 실측 자료가 아닙니다. 여러 발표·격자·측정 시점을 합친 테스트 배열은 병합 시 혼동을 드러내기 위한 것이며 단일 기관 요청의 결과를 재현한 것은 아닙니다.

| 자료 | 현재 응답 행 | 확인한 것 |
| --- | ---: | --- |
| 기상 예보 `response.body.items.item` | 48 | 발표 회차 2개, 격자 2개, 회차별 대상 시각 4개, TMP·REH·PCP 분리 |
| 기상 관측 같은 행 경로 | 12 | `obsrValue`, 기준 시각·격자 선택, 예보와 구분 |
| 대기 측정 `response.body.items` | 12 | 같은 측정 시각·측정소 선택, PM10·PM2.5·오존 단위 분리, 결측과 0 구분 |
| 포털 `data` | 12 | `matchCount`, 전체 12행과 마지막 값 11 보존 |
| 서울시 `culturalEventInfo.row` | 12 | 중첩 건수, 전체 12행과 마지막 가상행사 12 보존 |

붙여넣기 파서 → 행 인식 → 프로젝트 정규화 → 미리보기 문서 생성 → HTML 내보내기 → 재가져오기 → 코드 재실행의 데이터 계약을 확인했습니다. 96행의 원문 전체가 내보내기·재가져오기 뒤 동일했습니다. AI 맥락에는 8개 샘플만 전달되며 전체 실행 데이터와 구별됩니다.

재실행은 **Node VM과 작은 DOM 어댑터에서 내보낸 실제 스크립트를 실행**한 결과입니다. 브라우저 화면, 실제 iframe, 파일 선택/다운로드 버튼, CSP, 운영 인증·저장을 검증한 결과가 아닙니다. 검증용 예시 앱은 수작업으로 작성했으며 유료 AI가 만든 앱의 품질을 검증한 것도 아닙니다.

주요 기대 결과:

- 예보 TMP: 기준 `20261024 2300`, 격자 `60,127`, 대상 `20261025 0300~0600` 4행 평균 **-0.5℃**. 발표 회차를 `20261025 0200`으로 바꾸면 **9.5℃**. 대상 `0700` 하나만 선택하면 **11℃**, 격자를 `61,127`로 바꾸면 **31℃**.
- 같은 대상 시각에서 REH는 **57%**, PCP는 **1mm 미만** 원문을 표시하고 숫자로 더하지 않습니다.
- 관측은 예보와 다른 `obsrValue`를 사용해 **-3℃**를 표시합니다.
- 대기 PM10 `09:00`의 `10, -, 0`: 유효 2개·제외 1개, 평균 **5㎍/㎥**. 다른 시각의 `null`과 빈 문자열도 제외하고 유효한 0은 유지합니다. 마지막 `12:00` 검증-C 값은 **90㎍/㎥**, 오존은 **0.025ppm**입니다.
- 없는 예보 대상 시각과 연결 데이터 없음, 단일 객체·빈 배열·오류 응답, 알려진 인증 필드 거절, 용량·파일 수 제한을 확인했습니다.
- 기존 CSV 인용·줄바꿈, NEIS 행 선택, 전체 데이터 내보내기, HTML 주입 경계, 인증·저장·사용량 테스트를 함께 실행합니다.

## 수업에 적용하기 전 마지막 시연

1. 출력 폴더의 JSON을 확인합니다. 모두 가상 값이며 키와 학생 개인정보가 없습니다.
2. 접근 가능한 스튜디오에서 「로그인 없이 둘러보기」 → 「검증과 기록」 → 「백업 불러오기」로 `public-api-project.json`을 가져옵니다. 또는 JSON을 연결하고 예시 HTML을 가져옵니다.
3. 프로젝트 맥락에서 48·12·12·12·12행, 행 경로와 부분 응답 경고를 확인합니다. portal은 원본 전체 건수 999 때문에 다음 페이지 경고가 나오면 안 됩니다.
4. 미리보기에서 위 입력·기대 결과를 대조합니다. 새로고침 후에도 같은지 확인하고 HTML을 내려받아 새 브라우저 탭에서 동일하게 실행합니다.
5. 학생용 두 요청 초안을 열어 파일 활용과 실시간 연결이 다름을 확인합니다. 초안 선택만으로 AI 호출이 발생해서는 안 됩니다. 팀 계정 AI 검증은 별도로 수행합니다.

학생 안내: **“API로 이미 받은 응답을 파일이나 붙여넣기로 연결하면 저장된 시점의 자료로 앱을 만듭니다. 새로고침해도 기관의 새 자료를 받지 않습니다. 최신 자료 자동 조회는 별도의 서버 연결과 갱신·오류 처리가 필요합니다.”**

기상 항목·시각 구분은 앱 전체에 강제되는 계산 엔진이 아니라 AI 지침과 예시로 제공됩니다. 실제 팀 산출물마다 원자료와 비교해야 합니다. 키 탐지는 알려진 인증 필드에 한정되며 개인정보·모든 문자열의 키를 자동으로 보장해 제거하지는 않습니다.

## 추가 수업 사용 피드백: 한글 CSV와 설명 → 구현

- 파일 업로드가 `File.text()`의 UTF-8 읽기만 사용해 CP949 CSV의 한글 열 이름이 깨지는 현상을 가상 값으로 재현했습니다. 실제 성북구 원본 CSV는 이 대화에 제공되지 않았으므로 그 파일의 인코딩을 확정한 것은 아닙니다.
- 업로드 시 UTF-8을 우선 읽고 실패하면 EUC-KR/CP949를 시도합니다. BOM이 있는 UTF-16도 지원합니다. 잘못된 바이트·이미 저장된 깨진 문자·일부 호스트 디코더의 미해독 제어문자는 오류로 안내합니다. 모든 문자 인코딩을 자동 판별하는 기능은 아닙니다.
- 한글 열 이름이 AI 맥락과 HTML 내보내기까지 보존되는 테스트를 추가했습니다. 데이터의 값과 전체 행을 유지하며 기존 합계 용량 제한도 그대로 적용합니다. 이미 손실된 문자열을 추측해서 복구하지 않으므로 원본 파일을 다시 연결해야 합니다.
- 설명 모드는 계속 코드를 반환하지 않습니다. 빈 프로젝트의 설명 답변에는 「이 제안으로 첫 기능 만들기」를 추가해 선택한 제안이 담긴 만들기 모드 초안을 엽니다. 선택만으로 유료 AI를 호출하지 않습니다.
- 만들기 모드에서 기존 HTML이 없다는 이유로 새 앱 구현을 미루지 않도록 지침을 명확히 했습니다. 요청과 무관한 개인별 판단 용도를 새로 가정해 주의문을 붙이지 않도록 했으며, 프로젝트가 실제 그런 판단을 표방할 때의 한계 안내는 유지합니다.
- 자동화 테스트 54개, 구문 검사·빌드·diff 검사 통과. 새 전환 버튼의 실제 브라우저 실행과 유료 AI 응답은 미검증이며 운영 main에는 아직 반영하지 않았습니다.
