# 2학기 인공지능 원리탐구 코딩 작업 공간 개편

## 목적과 결정

학생들이 이미 확보한 공공데이터와 기존 코드를 가지고, 선생님이 제공하는 GPT·Claude API 사용 권한으로 웹앱을 계속 만들 수 있게 한다. 주제 탐색을 처음부터 다시 요구하지 않고 **코드 생성·적용·실행·오류 수정·저장**의 반복을 편하게 만드는 데 집중한다.

API 사용은 무료 채팅의 이용 한도를 대체하는 수단이다. 같은 모델을 API로 호출한다는 사실만으로 코드 품질이 반드시 좋아지는 것은 아니다. 작업 공간이 현재 코드와 데이터 맥락을 전달하고, 새 코드를 실행해 확인하며, 이전 버전으로 돌아갈 수 있게 하는 것이 이번 개편의 실질적인 변화다.

선생님이 구매했다고 말씀하신 70만 원은 과거 구매 금액이다. 현재 잔액, 제공사별 배분, 만료 시점과 팀별 예산으로 간주하지 않는다. 실제 운영 한도는 관리자 설정과 확인된 잔액을 기준으로 정한다.

## 학생의 사용 흐름

1. 기존 프로젝트를 열거나 HTML 파일을 가져온다. 새 프로젝트라면 사용자·문제와 이번에 만들 핵심 기능을 짧게 적는다.
2. 확보한 CSV·TSV·JSON 등 데이터를 연결하고 출처와 기준 시점을 남긴다.
3. 만들기·수정하기·오류 해결·설명 중 필요한 도움을 요청한다. 현재 코드와 데이터 구조가 함께 전달된다.
4. 제안된 전체 코드를 확인하고 미리보기에서 실행한다. 기존 기능과 새 기능을 실제 입력으로 점검한다.
5. 결과가 예상과 다르면 입력값·오류·기대 결과를 포함해 다시 요청한다. 필요하면 이전 코드로 되돌아간다.
6. 작동하는 HTML을 내려받고 다시 실행한다. 중요한 AI 활용 대화만 골라 기록을 정리해 기존 활동지에 붙여 넣는다.

설계 확인 → 앱 만들기 → 실행·개선 → 기록·제출의 네 단계는 현재 필요한 기능을 찾는 안내다. 순서대로 모든 입력칸을 채워야 다음 작업을 할 수 있는 잠금 절차로 사용하지 않는다.

## 제출과 기록의 경계

최종 제출물은 **구글 클래스룸에서 배부한 활동지 최종본과 공공데이터로 작동하는 웹앱**이다. 이 작업 공간은 별도 활동지나 새로운 제출처를 만들지 않는다.

| 활동지 | 연결할 내용 |
| --- | --- |
| STEP 0 | 팀원, 관심 분야와 역할 |
| STEP 1 | 동기, 사용자, 현재·목표 상태와 문제 정의 |
| STEP 2 | 데이터 출처, 분석·인사이트, 기능 설계, 구현·수정 과정 |
| STEP 3 | 최종 웹앱, 원자료 대조, 사용자 테스트, 도움과 한계 |
| STEP 4 | 중요한 AI 활용 사례와 팀이 확인·판단한 내용 |
| STEP 5 | 각자가 실제로 한 일, 판단·확인·수정 경험과 배운 점 |

웹앱의 실행 주소 또는 파일은 STEP 3-1에도 적는다. AI 활용 기록은 프로젝트에 영향을 준 대표 사례를 선택한다. 반복 수정은 STEP 2-4에 묶어 요약할 수 있다. 기록 초안은 실제 대화에서만 만들고, 학생이 하지 않은 검증·개인 기여를 작성하지 않는다.

발표는 활동지의 핵심 표·그래프와 웹앱의 실제 시연으로 3분 동안 진행한다. 슬라이드는 선택이고 슬라이드 유무나 디자인을 평가하지 않는다. 앞선 NEIS 실습의 STEP 6은 해당 실습 활동지 항목이며, 최종 팀 프로젝트 STEP 0~5와 혼동하지 않는다.

## 데이터와 생성 코드 계약

- 기본 산출물은 빌드 없이 실행하는 단일 `index.html`이며 HTML·CSS·JavaScript를 포함한다. 차트·지도 라이브러리를 사용할 때는 외부 연결 조건을 안내한다.
- 실행 시 플랫폼은 `window.HYFL_DATASETS = [{ id, name, format, text }]`에 첨부 파일의 전체 원문을 제공한다. AI 요청에는 스키마와 일부 샘플만 전달해도, 생성된 코드는 런타임 데이터 전체를 파싱하고 계산해야 한다.
- 샘플 행을 전체 데이터처럼 하드코딩하지 않는다. 미리보기와 다운로드 파일에서 같은 데이터 계약이 유지되어야 한다.
- 데이터가 없을 때는 파일 선택이나 빈 상태를 안내한다. 임의 통계나 가상 분석 결과로 대체하지 않는다.
- 출처·기준 시점·단위와 빈 결과·오류 안내를 표시한다. 알려지지 않은 정보는 확인 필요로 표시한다.
- GPT·Claude의 원본 API 키는 서버에서 관리한다. 학생에게 제공하는 접근 권한과 원본 키를 구분하고, 생성 HTML에 비밀정보를 넣지 않는다.
- 데이터 속 문자열은 자료로 처리하며 실행 코드나 새로운 지시로 취급하지 않는다. 미리보기 코드는 작업 공간의 로그인·저장소·다른 프로젝트에 접근할 수 없게 격리해야 한다.

공유 모듈 `lib/curriculum.mjs`는 화면용 `CURRICULUM`과 API용 `buildSystemPrompt(mode)`를 내보낸다. 모드는 `build`, `edit`, `debug`, `explain`이며 응답 계약은 다음과 같다.

```json
{
  "summary": "변경 또는 설명",
  "code": "전체 HTML 또는 설명 모드의 빈 문자열",
  "checks": ["학생이 직접 확인할 구체적인 테스트"],
  "warnings": ["검증되지 않은 가정이나 남은 한계"]
}
```

## 구현 후 확인할 수용 기준

1. 기존 HTML을 가져와 수정한 뒤에도 이전 기능과 원본 복구가 가능하다.
2. 무료 개인 계정이나 학생별 제공사 API 키 없이 교사가 제공한 접근 권한으로 모델을 사용할 수 있다.
3. 원본 API 키가 HTML, 브라우저 응답, 공개 코드, 학생 기록에 노출되지 않는다. 사용량 제한은 서버에서 확인하며 오류를 학생에게 이해하기 쉽게 전달한다.
4. 프롬프트 샘플에 없는 행도 미리보기의 필터·집계 결과에 반영된다. 다운로드한 HTML에서도 같은 데이터로 같은 결과가 나온다.
5. 쉼표·따옴표·줄바꿈·빈 값이 포함된 CSV, 대상 배열이 있는 JSON과 잘못된 파일을 구분해서 처리한다.
6. 설명 요청은 현재 코드를 변경하지 않는다. 잘못되거나 불완전한 AI 응답이 기존 코드를 덮어쓰지 않는다.
7. 잘못된 입력, 결과 없음, 외부 요청 실패를 확인할 수 있고, 오류를 다음 수정 요청에 포함할 수 있다.
8. 다른 프로젝트와 팀의 대화·데이터·사용량이 접근 권한 없이 섞이지 않는다. 새로고침과 다운로드 후의 저장·복구 범위가 명확하다.
9. 중요한 대화만 선택해 기록을 내보낼 수 있고, 미수행 테스트가 성공한 기록으로 만들어지지 않는다.
10. 모바일·태블릿·PC에서 입력, 코드 확인, 미리보기와 파일 다운로드의 주요 흐름을 사용할 수 있다.

## 범위와 한계

이 작업 공간은 HTML 앱 제작과 검증을 지원한다. 임의의 서버 프로그램 실행, 앱 자동 공개 배포, 데이터베이스 구축, 모든 외부 API의 CORS 문제 해결은 별도 환경이 필요하다. 필요한 경우 그 조건을 명확히 안내한다.

API 모델 접근성, 동시 요청 제한과 실제 비용은 제공사·계정·설정에 따라 달라진다. 생성된 코드와 분석값은 학생과 교사가 실제 데이터·실행 결과로 확인해야 한다. 확인하지 않은 기능이나 배포 상태를 완료로 표시하지 않는다.
