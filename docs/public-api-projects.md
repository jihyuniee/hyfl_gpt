# 공공 API를 팀 프로젝트로 연결하기

학생의 흐름은 **문제 → 필요한 값 → 공식 API 요청 → 응답 확인 → 작은 기능 → 원자료 대조**입니다. API를 썼다는 사실보다 사용자의 입력에 어떤 근거 있는 결과를 제공하는지가 중요합니다.

## 두 가지 완성 방식

| 방식 | 데이터 연결 | 제출·검증 |
| --- | --- | --- |
| 받아 둔 응답으로 제작 | JSON 응답 붙여넣기 또는 파일 추가 | HTML에 전체 응답 포함. 수집 시점과 조회 조건 표시. 최신·실시간 자료라고 쓰지 않기 |
| 실시간 조회 | 공식 서비스 문서와 실제로 준비된 서버 경로 사용 | 키는 서버에서 관리. CORS, 호출 한도, 실패 안내, 갱신 시점, 제출 환경에서 재실행 확인 |

실시간 서버를 준비하지 않아도 첫 번째 방식으로 문제 해결과 분석, 웹앱 구현을 완성할 수 있습니다. 이 스튜디오의 응답 붙여넣기는 외부 API를 호출하거나 누락된 다음 페이지를 자동 수집하지 않습니다.

## 수업에서 바로 연결할 질문

| 관심 분야 | 사용자·문제 예시 | 최소 기능 | 확인할 점 |
| --- | --- | --- | --- |
| 어문·문화 | 야외 문화행사를 준비하는 학생이 시간대별 날씨를 비교하고 싶다 | 행사 시간 선택 → 해당 시각 기온·강수 관련 항목 표시 | 관측/예보 구분, 발표·예보 시각, 격자, 단위·코드 의미 |
| 사회과학·환경 | 야외활동 계획자가 지역별 대기 정보를 비교하고 싶다 | 지역 선택 → 같은 시점·항목의 측정값 비교 | 관측소·지역 차이, 결측, 측정 시점·단위 |
| 사회과학·교통 | 행사 방문객이 대중교통 접근 정보를 찾기 어렵다 | 장소 선택 → 확보한 정류장·노선 정보 표시 | 좌표계, 정류장 ID, 조회 범위·갱신일 |
| 급식·학교생활 | 학생이 특정 날짜 식단을 조건별로 확인하고 싶다 | 날짜·식사 선택 → 실제 급식 행 표시 | NEIS row 경로, 요청 기간, 식사 구분, 알레르기 원문 |

이 표는 탐구 설계 예시입니다. 필요한 항목과 사용 가능한 서비스는 각 팀이 공식 문서와 실제 응답에서 확인합니다. 건강 위험이나 안전 여부를 데이터 하나로 단정하지 않습니다.

## 요청과 응답을 확인하는 순서

1. 공식 문서에서 서비스·기능과 필수 인자를 확인합니다. 기상청 단기예보 문서: https://www.data.go.kr/data/15084084/openapi.do
2. API 키는 해당 기관의 요청 도구에서 사용하고, AI 대화·HTML·저장소·출처 URL에는 옮기지 않습니다.
3. JSON 옵션으로 응답을 받습니다. 기상청의 경우 `dataType=JSON` 등 문서의 정확한 대소문자·인자명을 확인합니다. 날짜·발표 시각·격자도 문서 기준으로 선택합니다.
4. HTTP 성공만으로 데이터가 있다고 판단하지 않습니다. 응답 코드, 실제 행 배열, 현재 페이지 행 수, 전체 건수와 요청 조건을 확인합니다.
5. 응답 본문만 「프로젝트 맥락 → API 응답 붙여넣기」에 연결합니다. 개인정보·인증 정보가 없는지 먼저 확인합니다. 기존 파일 업로드도 가능합니다.
6. 「수업 가이드 → API 응답으로 기능 만들기」를 골라 팀의 입력·결과 조건으로 수정합니다. 전체 응답으로 계산하고 출처·시점을 표시하도록 요청합니다.
7. 같은 입력의 기대 결과를 원응답에서 찾아 앱과 비교합니다. 마지막 행, 결과 없음, 오류 응답도 확인합니다. 내보낸 HTML에도 데이터가 보존되는지 재실행합니다.

기상 데이터의 `category`가 다른 값을 한 합계로 묶지 않습니다. 요청 인자 `base_date`·`base_time`과 **응답 필드 `baseDate`·`baseTime`**(발표·기준 시각), `fcstDate`·`fcstTime`(예보 대상 시각)을 구분합니다. 관측은 `obsrValue`, 예보는 `fcstValue`를 읽습니다. 같은 대상 시각의 예보라도 발표 회차가 다르면 회차를 선택하고 기준을 표시합니다. 날짜가 넘어가는 예보도 발표일과 대상일을 함께 표시합니다. 격자(`nx`, `ny`)를 위도·경도로 취급하지 않습니다. 항목 코드·단위는 공식 문서로 확인합니다. TMP·T1H(℃), REH(%) 등을 서로 합산하지 않습니다. PCP의 `강수없음`·`1mm 미만` 같은 범주·범위 값은 원문으로 표시하고 임의로 0이나 1로 계산하지 않습니다. 환경 자료의 `dataTime`은 해당 서비스의 측정·통보 시각 의미를 확인하고, PM10·PM2.5(㎍/㎥)와 오존(ppm)을 섞지 않습니다. `-`, 빈 문자열, `null`은 유효한 0과 구분하고 집계에서 제외한 수를 표시합니다.

## 현재 구현의 범위

- NEIS, 기상청·공공데이터포털의 대표 응답, 서울시 row 형식을 지원합니다. 다른 중첩 구조와 여러 데이터 배열이 섞인 응답은 직접 구조를 확인해야 합니다.
- 데이터 파일 전체와 붙여넣은 전체 응답이 실행·내보내기에 포함됩니다. AI에 보이는 일부 샘플이 전체 행은 아닙니다.
- 기상·환경의 `totalCount`, 서울시·NEIS의 `list_total_count`와 현재 응답 행 수를 대조합니다. 공공데이터포털에서 `matchCount`가 있으면 조회 조건에 맞는 건수로 사용하고 원본 `totalCount`와 구분합니다. 오류 코드가 있는 서울시 응답은 정상 행으로 세지 않습니다.
- 알려진 오류 코드·페이지 누락 안내는 확인 보조 기능입니다. 응답이 이미 필터링되었거나 일부 기간만 포함된 상황까지 자동 판정하지 않습니다.
- 실시간 API 호출, 기관별 키 관리·프록시, 여러 페이지 자동 병합, XML 자동 변환은 이번 변경에 포함하지 않습니다.
- 최종 제출은 기존 구글 클래스룸의 활동지와 웹앱이며, 발표 슬라이드는 선택입니다.
